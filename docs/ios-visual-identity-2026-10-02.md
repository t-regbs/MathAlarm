# iOS visual identity — 2 October 2026

The native iOS presentation now uses Math Alarm's violet accent, rounded clock typography and a clock dial with arithmetic hour marks. Android supplies the color and emphasis cues; iOS retains its own SwiftUI navigation, grouped forms, native date picker, switches, menus, keyboard accessories and Liquid Glass controls. This is a presentation refinement after Milestone 6, not a change to the migration architecture or a new milestone completion claim.

## Design decisions

- Put identity into content: pale lavender panels in light mode, graphite and muted violet in dark mode, larger monospaced rounded times and equations, arithmetic clock illustrations, and restrained SF Symbol accents. Alarm cards show question count alongside time, title and recurrence.
- Keep the functional layer native. NavigationSplitView, NavigationStack, sheets, toolbar actions, swipe deletion, alerts and native form behavior remain intact. Use SwiftUI's glass button styles for the empty-list Add action, Submit, tone preview and announcement action. Content panels use solid adaptive colors rather than simulated glass.
- Start the alarm list and app settings directly with their content, without brand banners. The editor panel shows the actual draft time and weekdays; its decorative dial follows the draft time.
- Refine the editor dial at its existing 80-point size: a softly tinted adaptive face separates it from the lavender banner, with a fine rim and shallow shadow. The shorter hour hand is slightly heavier than the minute hand; a small contrasting center pin finishes their join. Four quieter arithmetic marks retain the app's signature, with eight short, low-contrast hour indices giving the face structure. Keep the hand tips clear of the symbols, including at cardinal times. Increased contrast strengthens the rim and marks and removes the decorative shadow. The clock remains a static, noninteractive SwiftUI vector illustration, hidden from accessibility alongside the separately spoken time; no seconds hand, minute scale or extra copy is introduced. Liquid Glass remains on native controls, following Apple's [materials guidance](https://developer.apple.com/design/human-interface-guidelines/materials).
- Keep the function symbol only as the supporting Challenge settings icon in the alarm editor. Announcement previews, alarm question counts, maths preview and question progress use text without that symbol. The system alarm's Solve Math action uses an open-app arrow. Alarm cards match Android's two-digit 12-hour clock with a smaller, localized AM/PM marker; the marker stacks below the digits when it cannot fit alongside them. Editor summaries and spoken alarm-time labels use the same display formatter. The native date picker retains its system behavior, and persisted hour/minute values are unchanged.
- Keep the empty list quiet: no brand panel, clock, or helper copy. Center the overlapping Android search artwork, “No alarms,” and a text-only Add alarm button in a scrollable viewport. The artwork is approximately 155 × 183 points, enlarged by 25% after the initial review. Extra bottom padding gives the group a small upward optical adjustment against the large navigation title; it scales down in short viewports and allows large text to scroll. `EmptyAlarmSearch.imageset/search_icon.png` is a byte-for-byte copy of Android's `drawable/search_icon.png`; the two-image offsets follow Android's existing arrangement. The unselected iPad detail has a simple text placeholder. Undo and pending-delivery actions remain available when applicable.
- Present What's New with a compact inline navigation title, centered native glass arrow buttons and page dots, then a full-width Try it action. Preserve the localized “Feature x of y” accessibility label and existing control identifiers. Browsing and acknowledgement behavior is unchanged.
- Keep tone selection quiet: the selected row uses the existing lavender highlight and native selected accessibility trait, without a trailing checkmark competing with the separate glass preview button. Staged selection, Done, Back/discard and preview ownership retain their existing behavior.
- Present the next-alarm summary as the native navigation subtitle beneath Math Alarm. This is an iOS counterpart to Android's floating next-alarm header: it follows the title and the navigation bar's own collapse/scroll-edge behavior, using the system typography without another content panel. Apple's [new navigation-bar design](https://developer.apple.com/videos/play/wwdc2025/284/) demonstrates this pattern in Mail for unread counts. Use the same shared occurrence calculation as Android for recurrence, skipped dates, persisted one-time dates and snooze; Swift formats the day/date and the app's localized 12-hour time. Show the summary only for enabled alarms without a scheduling error, and remove it when no upcoming occurrence remains. A presentation-only minute refresh and native activation/significant-time/time-zone notifications refresh the label without owning or changing scheduling.
- Present maths as a single focused task instead of a grouped settings form. A centered rounded equation sits on the canvas above one lavender answer field and a full-width native glass Submit answer button. Show question progress only for multiple questions, use a quiet alarm-title label when named, and let the Test Alarm navigation title identify previews without another banner. The answer field has a trailing native clear symbol, exposed as a separate accessible button; inline feedback retains its explicit dismissal and command retry. Snooze is a secondary action below Submit. A 480-point content limit keeps iPad readable. SwiftUI's native scroll alignment centers short content in the keyboard-adjusted viewport; focused-field scrolling runs only when content is taller than that viewport. Landscape and accessibility text can scroll. Large equations wrap at accessibility sizes instead of reducing Dynamic Type. The layout and trailing clear action follow Apple's [layout](https://developer.apple.com/design/human-interface-guidelines/layout) and [text-field guidance](https://developer.apple.com/design/human-interface-guidelines/text-fields). Shared answer validation, progress, preview ownership and delivered-alarm commands remain authoritative.
- Use semantic Dynamic Type fonts, system body text and automatic wrapping. Hide header dials at accessibility text sizes; stack alarm switches and tone actions vertically. Keep the spoken alarm labels, arithmetic labels, keyboard focus/scroll logic and existing automation identifiers.
- Package light, dark and increased-contrast variants for all five colors in Assets.xcassets. Accent-on-panel contrast is 5.89:1 in light mode, 6.85:1 in dark mode, 7.99:1 in increased-contrast light, and 9.90:1 in increased-contrast dark. Prominent controls have a separate, deeper violet tint: white-label contrast is 6.97:1 / 5.76:1 in light / dark, and 10.08:1 / 7.31:1 with increased contrast. The rendered dark-mode review exposed the need to separate text/symbol accent from prominent-button tint. These calculations describe solid colors, not every composited system control. Standard glass styles delegate reduced transparency and motion behavior to SwiftUI; the dial introduces no animation.

The separation of branded content from native controls follows Apple's [branding guidance](https://developer.apple.com/design/human-interface-guidelines/branding) and [materials guidance](https://developer.apple.com/design/human-interface-guidelines/materials). `NativeDesign.swift` owns the reusable presentation components and palette. The visual components preserve shared ViewModels, preferences, schemas, delivery queue, scheduling and persisted restoration. The permission-flow changes below add a narrow iOS tutorial audio-session lease while preserving real-alarm and preview priority; they do not change the shared UI split or scheduling rules.

The maximum-type client review also exposed native Back rehydrating the previous subpage after briefly returning to the editor. `NativeEditorNavigation` now skips hydration when its active stack is already initialized. A cached stack that regains ownership still hydrates its retained path, and new stacks retain the existing generation checks.

The ordinary iPhone client check then exposed the compact split view keeping a closed editor on screen after Cancel. `NativeApplicationRoot` now replaces the split container when its selected editor closes, so the list becomes visible. Feature ViewModels and the session registry remain outside the replaced container. `scripts/maestro/ios/native-editor-back-cancel.yaml` covers native Back followed by Cancel and an explicit return to the list.

The first Save now uses the existing native scheduler authorization bridge directly, once per retained permission result, and resumes Save only after a positive authorization result. An unsuccessful request offers an explicit Allow alarms retry without a premature Settings link. Denial preserves the draft and presents a native permission sheet with the Apps → Math Alarm → Alarms route and a silent looping illustration. Its single Go to Settings action starts native Picture in Picture and opens app Settings after AVKit confirms startup, so the guide follows the user into Settings. There is no separate Show me how or Watch action. Unsupported or failed PiP opens Settings directly. Returning after a grant saves the originating draft once; denial leaves it editable without another automatic request. Window sessions retain the request and Settings handoff, reject discarded or replaced drafts and yield to delivered challenges.

`NativeAlarmPermissionGuide.swift` owns video presentation and native AVKit controls. Nine localized six-second H.264 loops are generated by `scripts/generate_ios_alarm_permission_guide.swift`, with no recorded account data or audio tracks. The existing Kotlin platform audio manager grants an owner-scoped, mixing playback-session lease required by AVKit; real alarms and tone previews interrupt the guide. Tutorial cleanup cannot stop or deactivate a real alarm's audio. A separate Debug guide entry point exercises its UI and Settings link without creating or saving an alarm.
