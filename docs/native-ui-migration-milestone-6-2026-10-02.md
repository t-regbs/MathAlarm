# Milestone 6 — native settings and presentation parity

## Scope and authority

This change follows the [approved migration plan](native-ui-migration-plan.md), on `codex/ios-first-release` from verified `b938163`. History was checked against `41a97c7`, `ef7136c`, `4c2072a`, `f27063c` and `b938163`; the recorded M5 state was not assumed. No applicable repository instruction file was found. Unrelated IDE databases/state, deleted Kotlin error logs and Android release mapping are excluded.

**Milestone 6 is complete against its documented implementation/simulator gate.** Shared domain/application/data/ViewModel code, Room schemas, registration identities, preference/progress keys and native session coordinator are unchanged. Android remains Compose-owned; iOS remains SwiftUI; the framework remains `app` with the approved pinned bridge/toolchain versions. No Compose fallback, permanent XCTest target, CI expansion or experiment project was added. This does not establish physical reliability or release readiness; unavailable client checks are listed below.

The approved gate is: “Every feature in the parity table is implemented natively on iOS; nine locale catalogs and sound resources are packaged; permission and sharing flows behave correctly on iPhone/iPad; no omitted feature is disguised by a development placeholder.” All eight parity rows below have native implementation and current source/runtime evidence. Packaged catalog/tones checks, native permission guard/return and active-scene sharing/client cancellation pass on both form factors. First-install OS authorization and physical permission transitions remain unverified separately.
